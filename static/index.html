Dropped files are looked up on disk and rendered where they are, so their relative textures and linked files keep working. A copy into data/uploads is only made if you ask for it. You can also register a whole folder and every .blend inside is added.

Select .blend files

Browse and tick the .blend files you want to add.

Settings

Each job's output is set per scene: by default the folder saved in the .blend is used; you can change it in the scene overrides.

Output format

Applied when rendering, on an in-memory copy: the .blend file is never modified. With “the file's one” each scene keeps what it has.

Python scripts

It runs after the overrides, so it can change anything (including the format). If it raises, the job ends in error with the traceback in its log and nothing is rendered. The .blend is never modified: the changes live only in the Blender session that renders that job.

Existing frames

Blender either skips these files or replaces them, and it does it silently. Pick what this job should do — the .blend is not modified either way.

Where is this file?

The browser does not tell BlendQueue where a dropped file lives, and it was not found in the folders you already use. A copy cannot see the textures and linked .blend files next to the original, so they would render missing.
